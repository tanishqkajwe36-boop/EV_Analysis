Methodology & Data Engineering

Comprehensive audit of data cleaning procedures, schema validation, aggregation logic, and reproducibility instructions.

📦 Source Datasets & Pipeline

The analysis ingestion pipeline processes two raw partitions:

  • ev_market_train.csv: 200,000 raw observations across 37 columns.
  • ev_market_test.csv: 100,000 raw observations across 37 columns.

During automated cleaning, 1 duplicate vehicle ID was isolated and removed from the training split, resulting in exactly 199,999 valid vehicle records. Aggregates and charts are derived exclusively from this cleaned training split to preserve strict analytical validity.

🧹 Data Hygiene & Imputation Rules

The ingestion pipeline (src/build_data.py) applies deterministic cleaning rules:

  • Whitespace & Normalization: Categorical attributes are stripped of leading/trailing spaces and empty strings mapped to standard nulls.
  • Numeric Type Casting: All measures (range, battery, price, sales) cast to 64-bit numeric types.
  • Missing Value Imputation: Missing numeric values imputed using the segment-wide median; missing text mapped to Unknown.
  • Boundary Enforcement: Ratings constrained to [0.0, 5.0]; invalid negative prices or capacities clamped to 0.

📊 Interpretation Guidelines

The source dataset reflects a high-fidelity synthetic / benchmark mobility distribution:

  • annual_sales_units represents vehicle model-level performance estimates. Row sums should not be construed as statutory national vehicle registrations.
  • The training split was retained for exploratory, descriptive, and spatial visualization. The test split is held separately in the SQLite database to avoid data leakage.
  • All KPI percentages and averages are cross-verified between SQLite queries and Pandas aggregations.

⚡ Local Reproducibility

The pipeline can be executed in any Python 3.10+ environment:

  • Rebuild database & CSVs: python src/build_data.py
  • Run validation tests: python src/validate_project.py
  • Launch local web application: python app.py

Database schema, index definitions, and sample analytic SQL scripts are located in the sql/ folder.
